# CallLive 15.0.9 — монитор телефонии для FreePBX 15

Панель **Отчёты → Монитор телефонии** показывает текущие разговоры, номера и транки. В версии 15.0.9 обновлены вкладки, счётчики и таблица. Маршрут разговора позволяет выбрать событие и увидеть его время на графиках качества, потерь, джиттера и RTT.

## Что доступно

| Раздел | Возможности |
| --- | --- |
| Сейчас | Участники и каналы вызова; транки; состояния номера; качество 0–100%; суточный пик одновременных разговоров и самый длинный разговор |
| Технические детали | Каналы, кодеки, RTP/RTCP, объяснение оценки, покрытие и время замеров, четыре графика и лента событий |
| История | Завершённые вызовы, поиск по номеру или каналу и датам, фильтр низкого качества, последнее и худшее качество; открытие сохранённой карточки |
| События | Дозвон и результат, разговор, очередь, удержание, перевод, завершение и Cause/Cause-txt — по доступным событиям AMI |
| Проблемы | Фильтры низкого качества, потерь и долгого ожидания; уведомления в открытой панели с задержкой для устойчивой проблемы |
| Статистика | Завершённые вызовы и ответившие, дневные/часовые пики разговоров, суточная длительность, пик одновременно используемых каналов каждого транка |
| Диагностика | Версии модуля и сборщика, их совместимость, AMI, давность снимка, Python, запись истории, лимиты и root-команда обновления |
| Номера и транки | Кликабельные карточки с DND, FWD, Follow Me, устройствами, SIP-регистрацией и доступными параметрами |

Карточка не закрывается после отбоя. Её можно повторно открыть из истории после закрытия браузера. История начинает накапливаться после запуска нового сборщика; старые разговоры автоматически из CDR не импортируются.

## Совместимость

FreePBX **15 с Core**, Linux с **systemd**, **Python 3.6+** и стандартной библиотекой. Модуль не требует pip, SQLite или дополнительного PHP-драйвера. Сборщик подключается только к локальному AMI `127.0.0.1`. Замеры аудио доступны для SIP/PJSIP, когда Asterisk предоставляет RTP/RTCP; при прямом RTP через АТС данных может не быть. OffHook отображается, когда АТС действительно получает соответствующий сигнал.

Совместимая пара — модуль **15.0.9** и сборщик **15.0.8**. Если сборщик 15.0.8 уже работает и история доступна, обновите только веб-модуль. При первой установке или переходе со сборщика 15.0.4–15.0.7 выполните команду установки сборщика.

## Установка и упрощённое обновление

1. Перед обновлением рабочей АТС сохраните резервную копию. Скачайте `freepbx15-calllive-15.0.9.tar.gz` и команду подписи из [комплекта 15.0.9](https://github.com/shayena84-byte/freepbx-calllive/tree/main/dist/15.0.9).
2. В FreePBX откройте **Администрирование → Module Admin → Upload Module** и загрузите архив. В **Local Module Administration** выберите **Монитор телефонии → Install/Upgrade → Process → Confirm**.
3. Вставьте весь текст файла `calllive-15.0.9-sign-root-command.txt` в root-консоль АТС и дождитесь сообщения о действительной подписи. Затем нажмите **Apply Config**.
4. Откройте **Отчёты → Монитор телефонии → Диагностика**. При первой установке или со старым сборщиком выполните от root команду из этой вкладки. Для стандартного веб-каталога используйте команду ниже.

   ```bash
   bash /var/www/html/admin/modules/calllive/deploy/update-root.sh
   ```

   При нестандартном `AMPWEBROOT` используйте команду из диагностики или файл `calllive-15.0.9-update-root-command.txt`. Этот файл определяет путь из конфигурации FreePBX.
5. В диагностике проверьте модуль **15.0.9**, сборщик **15.0.8**, совместимость, AMI и доступность истории. Сделайте тестовый звонок, завершите его и откройте карточку в истории.

При первой установке root-команда создаёт пользователя службы, отдельную локальную учётную запись AMI и запускает сборщик. Используется порт 5038. Если AMI работает на другом порту, предварительно создайте `/etc/freepbx-calllive.env` с фактическим портом и действующими реквизитами, как показано ниже. `manager.conf` должен подключать `manager_custom.conf`.

### Что делает root-команда

- Проверяет FreePBX 15, контрольные суммы файлов, Python 3.6+ и локальный AMI.
- Находит действующий Python, включая `/usr/bin/python3.6`. Пакеты ОС не заменяются.
- Сохраняет предыдущие файлы сборщика, службы, окружения и локальной AMI-конфигурации в закрытую резервную копию `/var/backups/freepbx-calllive/…`.
- Сохраняет существующие реквизиты AMI, `daily.json`, историю и systemd drop-ins.
- Устанавливает `collector.py`, `telemetry.py`, метаданные и unit, затем перезапускает службу сборщика.
- Ждёт свежий снимок версии 15.0.8 с работающим AMI и записью истории. При ошибке возвращает предыдущие файлы и состояние запуска службы.
- Выводит путь резервной копии и готовую команду ручного отката.

Перед изменениями можно выполнить только проверку:

```bash
bash /var/www/html/admin/modules/calllive/deploy/update-root.sh --check-only
```

Для отката укажите **точный каталог**, напечатанный при обновлении:

```bash
bash /var/www/html/admin/modules/calllive/deploy/update-root.sh --rollback /var/backups/freepbx-calllive/КАТАЛОГ_КОПИИ
```

Откат касается сборщика, unit и AMI-конфигурации. Данные истории остаются на диске. Модуль в Module Admin откатывается отдельно установкой архива предыдущей версии и соответствующей подписью. После возврата старого сборщика новые функции панели могут быть недоступны — диагностика это покажет.

### Учётная запись AMI

Стандартная конфигурация хранится в `/etc/asterisk/manager_calllive.conf`:

```ini
[freepbx-calllive]
secret = СЛОЖНЫЙ_ЛОКАЛЬНЫЙ_СЕКРЕТ
deny = 0.0.0.0/0.0.0.0
permit = 127.0.0.1/255.255.255.255
read = call,agent
write = reporting
displayconnects = no
eventfilter = Event: (Newchannel|Newstate|NewCallerid|NewConnectedLine|Hangup|DialBegin|DialEnd|BridgeCreate|BridgeDestroy|BridgeEnter|BridgeLeave|BridgeMerge|ExtensionStatus|Hold|Unhold|ParkedCall|UnParkedCall|ParkedCallTimeOut|ParkedCallGiveUp|BlindTransfer|AttendedTransfer|QueueCallerJoin|QueueCallerLeave|AgentConnect|AgentComplete)
```

В `manager_custom.conf` должна быть строка `#include manager_calllive.conf`. Команда обновления добавляет её для стандартной учётной записи. У этой учётной записи нет разрешения выполнять управление звонками. AMI использует свойство `write` для допуска к запросам; `reporting` нужен для действий чтения списков.

Окружение службы `/etc/freepbx-calllive.env`, владелец `root`, права `0600`:

```ini
CALLLIVE_AMI_USER=freepbx-calllive
CALLLIVE_AMI_PORT=5038
CALLLIVE_AMI_SECRET=ТОТ_ЖЕ_СЕКРЕТ
```

Если используется собственное имя AMI-пользователя, обновление проверит подключение, но не перепишет его файл доступа. Администратору нужно добавить `read=call,agent` и разрешить события переводов/очередей в фильтре самостоятельно. Иначе соответствующая часть ленты событий будет неполной.

### Запуск и проверка службы

```bash
systemctl status freepbx-calllive.service --no-pager -l
journalctl -u freepbx-calllive.service -n 50 --no-pager
systemctl restart freepbx-calllive.service
```

Проверка только подключения к AMI:

```bash
(
    set -a
    . /etc/freepbx-calllive.env
    set +a
    CALLLIVE_PYTHON="$(command -v python3 || command -v python3.6)"
    PYTHONDONTWRITEBYTECODE=1 "$CALLLIVE_PYTHON" /opt/freepbx-calllive/collector.py --check
)
```

Версия сборщика без подключения:

```bash
/usr/bin/python3.6 /opt/freepbx-calllive/collector.py --version
```

Замените путь Python, если на вашей АТС он другой. Действующий интерпретатор виден в `systemctl cat freepbx-calllive.service`. Проверка `--check` выводит только версию и количество каналов/hints; секрет не печатается.

## Доступ пользователя

В **Администрирование → User Management → Users → выбранный пользователь → Administration GUI**:

- **Allow Administration Login → Yes**.
- **Grant Full Administration Rights → No**.
- В **Administration Access / Admin Sections** выберите **Монитор телефонии**.
- Сохраните. Пользователь должен выйти и войти заново.

Для **Администрирование → Administrators** выберите раздел **Монитор телефонии** в разрешённых разделах.

Разрешение `calllive` даёт чтение всей АТС: текущих и сохранённых вызовов, номеров, транков и технических деталей. Диапазон Visible Extension Range не ограничивает данные CallLive. Полные права нужны для изменения общих порогов и отображения команды обновления. Выполнение обновления и подписи требует root на сервере.

## История и хранение

По умолчанию сохраняются **30 календарных дней**, включая текущий, по времени АТС. Архив ограничен **512 МиБ**. Подробности содержат метаданные и замеры; звук разговоров, SIP-пароли и содержимое SIP-пакетов не записываются.

| Путь | Содержимое |
| --- | --- |
| `/run/freepbx-calllive/snapshot.json` | Текущий снимок; устаревает через 18 секунд |
| `/var/lib/freepbx-calllive/daily.json` | Суточные рекорды, совместимые с предыдущими сборщиками |
| `/var/lib/freepbx-calllive/active.json` | Контрольный список активных записей |
| `/var/lib/freepbx-calllive/live/` | Последние технические сведения об активных вызовах |
| `/var/lib/freepbx-calllive/archive/YYYY-MM-DD/` | Законченные карточки JSON и дневной каталог JSONL |
| `/var/lib/freepbx-calllive/statistics.json` | Статистика наблюдений по дням и часам |

Обычные записи обновляются примерно раз в пять секунд; завершение фиксируется после проверки исчезновения каналов. При перезапуске последняя сохранённая запись восстанавливается с пометкой пропуска наблюдения. Пропавший во время отключения AMI вызов не получает вымышленную причину отбоя.

Чистка запускается раз в пять минут. Сначала удаляются дни старше срока хранения, затем старейшие предыдущие дни при превышении объёма. Если текущий день уже заполнил лимит, новые законченные карточки не записываются до освобождения места; это явно отмечается в панели и диагностике. Активные контрольные файлы и сводная статистика имеют отдельные технические ограничения и не входят в 512 МиБ архива. Открытая карточка остаётся доступна до закрытия, даже если запись уже удалена из архива.

Для изменения лимитов добавьте в `/etc/freepbx-calllive.env` и перезапустите сборщик:

```ini
CALLLIVE_RETENTION_DAYS=30
CALLLIVE_HISTORY_MB=512
```

Допустимы 1–365 дней и 32–8192 МиБ. Для одного поиска и просмотра статистики выбирается диапазон до 31 дня. Страница истории выдаёт до 50 строк; **Ещё вызовы** продолжает поиск. Очень большой поиск ограничен по времени, с возможностью продолжения.

В длинной карточке сохраняется до 720 точек графика, меньше при большом количестве каналов. При сокращении сохраняется худшая точка каждой соседней пары с настоящим временем. Последнее и худшее качество хранятся отдельно от сокращённого графика. Ограничение — 500 событий и 64 канала на запись; интерфейс отмечает сокращение. Статистика относится к периодам, когда сборщик наблюдал АТС. Счётчики завершённых вызовов группируются по Linkedid; отдельные консультационные вызовы при переводах могут иметь собственную запись.

Даты каталога/поиска и суточные границы относятся к АТС. Время событий отображается в часовом поясе браузера. Учитывайте это при работе с АТС в другом часовом поясе.

## Как рассчитывается качество

Оценка — **расчётный индикатор 0–100%**, основанный на RTP/RTCP. Это не MOS и не анализ разборчивости речи.

```text
Качество канала = round(100 × F(потери) × F(джиттер) × F(RTT))
Качество разговора = минимум среди измеренных каналов
```

| Показатель | Коэффициент 1 | Коэффициент 0 |
| --- | --- | --- |
| Потери | ≤ 0,1% | ≥ 10% |
| Джиттер на приёме в АТС | ≤ 20 мс | ≥ 100 мс |
| RTT | ≤ 150 мс | ≥ 800 мс |

Между границами коэффициент уменьшается линейно. Потери по входящему направлению делятся на сумму принятых и потерянных пакетов; по исходящему — на отправленные пакеты. Используется худшая доступная доля потерь. Нужны минимум 20 пакетов и хотя бы один временной показатель — джиттер либо RTT. Недоступные значения не считаются нулевыми потерями; карточка показывает полноту замеров. Время и смысл счётчиков зависят от драйвера Asterisk: график потерь не является оценкой потерь строго между соседними точками.

Расшифровка показывает коэффициенты по каждому каналу, последнее/худшее качество, время и покрытие. Графики отображают качество, потери, джиттер и RTT; можно выбрать конкретный канал. При отсутствии данных показывается прочерк/«Замеры недоступны».

## Фильтры, уведомления и статистика

Во вкладке **Сейчас** выберите все проблемы, низкое качество, потери или долгое ожидание. Уведомление появляется, когда условие сохраняется заданное время. По умолчанию: качество ниже **65%**, потери выше **2%**, ожидание дольше **30 с**, устойчивость **10 с**. Отсчёт устойчивости начинается с обнаружения проблемы в открытой панели. После перезагрузки страницы начинается заново. Внешние сообщения не отправляются.

Администратор меняет пороги в **Диагностика → Пороги уведомлений**. Параметры сохраняются в БД FreePBX и действуют для всех пользователей. Запрос защищён сессией и CSRF-токеном.

Статистика показывает дневной и часовой пик, число законченных вызовов и вызовов с подтверждённым ответом, суточный максимум длительности и пик каналов каждого сопоставленного транка. Для часов без наблюдения используется отдельный цвет. Количество часов наблюдения помогает отличить нулевую нагрузку от остановленного сборщика. Указанная длительность разговора — сумма наблюдавшихся периодов медиа-соединения; ожидание/IVR не считаются подтверждённым разговором.

## Локальная подпись

Подписывайте **после установки конкретной версии**, когда файлы окончательные. Для архива 15.0.9 используйте скрипт подписи 15.0.9.

Откройте `calllive-15.0.9-sign-root-command.txt` на компьютере и вставьте весь текст в root-консоль АТС. Если PHP-скрипт уже на сервере, выполните его командой ниже.

```bash
php /путь/calllive-15.0.9-sign-local.php
```

Скрипт проверяет SHA-256 всех файлов установленного модуля и отсутствие лишних файлов. Затем создаёт или повторно использует локальный RSA-ключ, формирует оба уровня подписанных списков FreePBX и проверяет результат через API подписи FreePBX. При отказе возвращает прежние файлы подписи.

Ключ хранится в `/etc/freepbx.secure/calllive-key` с доступом только root; публичный ключ импортируется в кольцо пользователя FreePBX. Никому не передавайте закрытый ключ или резервную копию с ним. В GitHub публикуются исходники и код подписи, без ключей и локальных секретов. Это **локальная подпись вашей АТС**, а не официальная подпись Sangoma и не автоматическое доверие на чужих серверах. После ручного изменения любого файла модуля проверка эталонного релиза откажет — установите исходный архив либо подготовьте отдельный релиз.

## Проверка и диагностика

После обновления проверьте внутренний и внешний звонки, замеры через 5–15 секунд, сохранение карточки после отбоя и повторное открытие в истории. Затем проверьте карточки номера/транка и вход пользователя только с разрешением `calllive`.

При отсутствии свежих данных:

```bash
systemctl status freepbx-calllive.service --no-pager -l
journalctl -u freepbx-calllive.service -n 50 --no-pager
stat -c '%a %U:%G %n' /run/freepbx-calllive /run/freepbx-calllive/snapshot.json /var/lib/freepbx-calllive
df -h /run /var/lib/freepbx-calllive
```

- **Нет данных от сборщика**: служба, путь снимка, права группы веб-процесса, давность >18 с.
- **AMI недоступен / ошибка входа**: локальный порт, секрет, ACL. Проверьте `--check`.
- **AMI отклонил запрос**: права `reporting`, действия CoreShowChannels, BridgeList, ExtensionStateList и журнал службы.
- **История не сохраняется**: место на диске, владелец/группа `/var/lib/freepbx-calllive`, лимит архива.
- **Нет части событий переводов/очередей**: права `read=call,agent` и eventfilter.
- **Не совпадают версии**: после загрузки архива выполните root-команду обновления сборщика.
- **Предупреждение о подписи**: используйте файл подписи именно этой версии и проверьте конечное сообщение её успешной проверки.

На нестандартных установках группа службы должна совпадать с группой веб-процесса FreePBX. Существующие systemd drop-ins сохраняются; установите корректные `User=`, `Group=`, `ExecStart=` через `systemctl edit freepbx-calllive.service`.

## Удаление

Остановите `systemctl disable --now freepbx-calllive.service`, удалите модуль в Module Admin. Затем при необходимости удалите локальную AMI-учётную запись/её include, `/etc/freepbx-calllive.env`, unit и `/opt/freepbx-calllive`, выполните `systemctl daemon-reload` и `asterisk -rx 'manager reload'`. История, резервные копии и ключи автоматически не удаляются. Решение об их удалении принимает администратор отдельно.
