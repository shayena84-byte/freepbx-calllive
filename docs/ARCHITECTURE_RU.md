# Устройство CallLive 15.0.8

## Поток данных

Сборщик `collector.py` работает отдельной systemd-службой на сервере АТС. Единственное сетевое подключение — локальный AMI. `CoreShowChannels`, `BridgeList`, `ExtensionStateList` дают сверяемое состояние; события обновляют его между полными запросами. SIP/PJSIP опрашиваются через `Status` и `Getvar` для форматов и RTCP. Снимок публикуется атомарной заменой JSON с правами `0640`.

PHP-модуль проверяет сессию, разрешение `calllive`, её срок и включённость модуля. Текущий снимок старше 18 секунд не используется. Справочник номеров/транков читается из FreePBX. Детали услуг номера и SIP собираются фиксированными запросами чтения AMI с ограничением по времени.

Браузер запрашивает состояние примерно раз в секунду; технический журнал открытой карточки — раз в пять секунд до завершения. Завершённая карточка остаётся в окне и на диске. История и статистика загружаются по запросу. Для графиков используется локальный SVG; внешних CDN/аналитики нет.

## Журнал

Постоянный каталог — `/var/lib/freepbx-calllive`. `active.json` содержит идентификаторы контрольных записей в `live/`. В `archive/YYYY-MM-DD/` публикуется отдельный подробный JSON вызова и добавляется краткая строка в `catalog.jsonl`. Писатель один; PHP читает каталоги под разделяемой блокировкой. Подробные файлы и статистика заменяются атомарно. При частичной записи/сбое повторный идентификатор в каталоге безопасно отфильтровывается читателем.

Идентификатор записи состоит из даты наблюдения и 24 шестнадцатеричных символов хеша Linkedid/времени. Web API не принимает произвольный путь. Контрольные файлы не содержат секретов AMI, аудио или неотфильтрованных заголовков SIP. Каналы записываются из фиксированного набора полей. AMI-события также переводятся в ограниченную схему.

Запись группируется по Linkedid; группировка текущей строки по медиа-мостам остаётся прежней. Это позволяет сохранять цепочку обычного перевода, не объединяя независимые консультационные вызовы только потому, что они попали в общую конференцию. Для сложной топологии у одного логического вызова могут быть несколько строк, а консультация — отдельная историческая запись.

Пропуски AMI и перезапуски маркируются. При повторном подключении исчезнувшие каналы завершаются как `interrupted`, без выдуманной причины и времени после последнего наблюдения. Вызовы без полученного события Hangup имеют `unobserved_end`. Точная длительность неизвестного периода не добавляется к разговору.

Срок по умолчанию — 30 календарных дней, архив 512 МиБ. При исчерпании текущего дня пропускаются новые законченные записи с индикатором в диагностике. Ограничены число активных записей, каналы, события, точки и размер файлов. Длинные ряды сокращаются выбором худшего балла в соседних парах; последнее и худшее качество сохраняются отдельно. Метрики графиков — фактически доступные счётчики и времена, не измерение речи.

## API и права

Все ответы: `Cache-Control: no-store, private`. Разрешение `calllive` — глобальный просмотр АТС; диапазон внутренних номеров FreePBX не применяется к этому разрешению.

| Команда | Метод | Доступ | Данные |
| --- | --- | --- | --- |
| `snapshot` | GET | calllive | Снимок, версии, пороги, суточные максимумы; inventory=1 добавляет справочник |
| `extension`, `trunk` | GET | calllive | Конфигурация и состояние сущности, без секретов |
| `history` | GET | calllive | Даты, номер/канал, до 50 результатов, курсор продолжения |
| `call` | GET | calllive | Сохранённая или активная подробная запись по проверенному ID |
| `statistics` | GET | calllive | Дневные/часовые наблюдения и пики конечных точек |
| `diagnostics` | GET | calllive | Состояние служб по снимку, версии, наличие файлов; root-команда только полному администратору |
| `settings` | POST | Полный администратор + CSRF | Общие пороги уведомлений в таблице calllive_settings |

Выборка истории ограничена диапазоном дат до 31 дня, строками каталога до 16 КиБ, числом прочитанных строк и временем. Курсор — проверенные дата/байтовая позиция, не имя файла. Сами события не применяются к конфигурации АТС. Web API не запускает команды ОС и не перезапускает службы.

## Качество и статистика

`quality()` в Python и `channelQuality()` в JS используют одну шкалу: `100 × F(loss) × F(jitter) × F(rtt)`, минимум среди измеренных каналов. Границы 0,1–10% потерь, 20–100 мс джиттера, 150–800 мс RTT. `null` означает отсутствие замера. Для вычисления нужен хотя бы один валидный показатель потерь и один времени; неполные данные маркируются. Сама шкала описана в полном руководстве и в карточке. Это эвристика, не MOS.

`LiveConversations` фиксирует короткие соединения между полными снимками. Дневные пики совместимы с прежним `daily.json`; исторические дневные/часовые пики и пики endpoint сохраняет `Journal`. Справочник FreePBX сопоставляет endpoint транкам в интерфейсе. Счётчики законченных вызовов учитываются по дню начала и не равны числу SIP-каналов. Часы без наблюдения отличаются от нулевой нагрузки. Для защиты от повторной фиксации после перезапуска статистика сохраняется до контрольного списка активных записей и содержит ограниченный список последних учтённых ID.

## Обновление и подпись

`update-root.sh` читает уже установленный модуль. Сначала проверяет среду и SHA-256, затем резервирует фиксированный набор путей. Python выбирается из действующего ExecStart или известных путей, включая Python 3.6. Реквизиты и systemd drop-ins сохраняются. Проверка результата требует свежего снимка версии релиза, AMI ready и доступной записи журнала. Ошибка вызывает восстановление файлов; итог возврата явно выводится. Это локальная команда root, а не удалённое выполнение из PHP.

CLI-подпись в `dist/15.0.8` содержит эталонные SHA-256 каждого файла архива. Она проверяет отсутствие дополнительных файлов, создаёт подписанный список в `/etc/freepbx.secure/calllive.sig` и внешний `module.sig`, импортирует открытый ключ и проверяет FreePBX GPG status. Закрытый ключ остаётся на АТС. Подписывается конечный набор файлов модуля после его установки; код обновления не меняет этот набор.
