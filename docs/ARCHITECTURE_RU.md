# Как устроен CallLive 15.0.6

Asterisk передаёт события и состояние через AMI. Сборщик объединяет эти данные в снимок. PHP-модуль FreePBX проверяет сеанс администратора и отдаёт снимок со справочником АТС. JavaScript сопоставляет каналы с номерами и транками, строит таблицы и считает качество.

| Файл | Ответственность |
| --- | --- |
| [module.xml](../calllive/module.xml) | Имя модуля `calllive`, версия, пункт в меню **Отчёты**, зависимость от Core и FreePBX 15 |
| [page.calllive.php](../calllive/page.calllive.php) | Каркас панели, таблицы, карточки вызова, номера и транка |
| [Calllive.class.php](../calllive/Calllive.class.php) | Доступ к странице и AJAX, чтение снимка, справочник FreePBX, подробности номера и транка |
| [collector.py](../calllive/deploy/collector.py) | Локальный клиент AMI, группировка вызовов, суточная статистика и замеры RTP/RTCP |
| [freepbx-calllive.service](../calllive/deploy/freepbx-calllive.service) | Запуск Python под отдельным пользователем, окружение, каталог снимка и перезапуск при сбое |
| [calllive.js](../calllive/assets/js/calllive.js) | Опрос API, сопоставление участников, оценка качества и обновление интерфейса |
| [calllive.css](../calllive/assets/css/calllive.css) | Компактный заголовок, таблицы, цветовые метки и адаптивные карточки |

## Сборщик

### AMI и жизненный цикл снимка

- [`Ami.exchange()`](../calllive/deploy/collector.py#L88) добавляет `ActionID` к каждому действию и принимает ответ до заданного срока. События, пришедшие между частями ответа, передаются обработчику. Это позволяет собирать списки и отслеживать вызовы по одному соединению.
- [`LiveEvents`](../calllive/deploy/collector.py#L125) хранит признаки, которые приходят через события, включая направление вызова и удержание. `capture()` запрашивает каналы, мосты и hints действиями `CoreShowChannels`, `BridgeList` и `ExtensionStateList`. Для hints используется стандартный контекст FreePBX `ext-local`.
- [`run_session()`](../calllive/deploy/collector.py#L560) снимает состояние примерно раз в 5 секунд и по событиям с минимальным интервалом 0,75 секунды между пересъёмками. При разрыве соединения `main()` публикует причину недоступности и повторяет подключение с задержкой до 15 секунд.
- [`write_json()`](../calllive/deploy/collector.py#L540) сначала пишет JSON во временный файл в том же каталоге. Затем заменяет прежний снимок одним переименованием. У снимка схема `1`, время `updated_at` и предел 4 МиБ.

Сервис хранит актуальный снимок в `/run/freepbx-calllive/snapshot.json` с правами `0640`. Веб-процесс читает его через группу, заданную в unit. `/run` очищается при перезагрузке системы. Служба создаёт каталог и снимок заново.

### Разговоры и суточные счётчики

[`group_calls()`](../calllive/deploy/collector.py#L195) собирает разговоры из каналов `Up`, участвующих в медиамостах `simple_bridge`, `native_rtp` и `softmix`. Он связывает мосты через парные половины `Local`, исключает служебные каналы из списка участников и определяет состояние разговора. Каналы вне подтверждённого медиамоста группируются по связанному ID для показа дозвона, очереди, парковки и других стадий.

[`LiveConversations`](../calllive/deploy/collector.py#L348) отслеживает короткие разговоры по событиям между полными снимками. [`DailyStats`](../calllive/deploy/collector.py#L284) хранит пиковое число одновременных соединений и максимальную продолжительность соединения в текущем календарном дне. Смена суток определяется по местному времени АТС. Для разговора через полночь суточная длительность после полуночи отсчитывается от начала нового дня.

Данные суточной статистики сохраняются в `/var/lib/freepbx-calllive/daily.json`. При новом запуске сборщик читает их и сверяет активные мосты с Asterisk. Таймер **С начала вызова** в таблице показывает возраст старейшего активного канала в группе. Суточный максимум длительности относится к времени подтверждённого разговора в пределах суток.

### Замеры RTP/RTCP

[`LiveMedia`](../calllive/deploy/collector.py#L474) получает форматы каналов через `Status` и опрашивает SIP-каналы подтверждённых соединений через `Getvar`. Для PJSIP используется `CHANNEL(rtcp,all)`, для chan_sip — `CHANNEL(rtpqos,audio,all)`. Опрос распределён по каналам. Один проход ограничен 32 запросами `Getvar` и общим временем 0,65 секунды. Последние замеры хранятся до 15 секунд.

[`rtp_stats()`](../calllive/deploy/collector.py#L434) проверяет поля счётчиков, переводит локальный джиттер и RTT в миллисекунды и использует `null` для недоступных значений. Отчёт RTCP от удалённой стороны подтверждает наличие данных о потерях на приёме у неё. Значения зависят от того, какие пакеты и отчёты видит Asterisk. При прямой передаче медиа часть замеров может быть недоступна. [Asterisk CHANNEL](https://docs.asterisk.org/Latest_API/API_Documentation/Dialplan_Functions/CHANNEL/)

## FreePBX и права доступа

[`canView()`](../calllive/Calllive.class.php#L24) проверяет активный сеанс администратора, доступ ко всем разделам, диапазон внутренних номеров и статус модуля. [`ajaxRequest()`](../calllive/Calllive.class.php#L43) допускает только авторизованные `GET` к командам ниже. Ответы помечены `Cache-Control: no-store, private`.

| Команда | Источник |
| --- | --- |
| `snapshot` | JSON сборщика. Снимок старше 18 секунд считается недоступным. С `inventory=1` добавляются номера, устройства и транки из БД FreePBX |
| `extension` | Сведения о номере и устройствах из БД, DND, переадресация, ожидание второго вызова и Follow Me из AstDB, детали SIP из AMI |
| `trunk` | Параметры и исходящие маршруты из БД, сведения SIP и статус исходящей регистрации PJSIP, если АТС его предоставляет |

Для карточек номера и транка PHP валидирует идентификаторы, освобождает блокировку сеанса и выполняет фиксированный набор запросов с ограничением по времени. Они используют штатное AMI-соединение FreePBX. Сборщик использует собственную учётную запись, ограниченную локальным адресом и правами, описанными в [руководстве](OPERATIONS_RU.md#учётная-запись-ami).

## Интерфейс и качество

[`refresh()`](../calllive/assets/js/calllive.js#L736) читает свежий снимок примерно раз в секунду. Справочник запрашивается реже. [`buildLookups()` и `assign()`](../calllive/assets/js/calllive.js#L111) связывают каналы с устройствами по hints и настройкам, затем определяют внутренний номер или транк. При неоднозначном соответствии виден канал Asterisk. Статус **Снята трубка** появляется, когда АТС передаёт OffHook по сопоставленному каналу.

[`channelQuality()`](../calllive/assets/js/calllive.js#L239) использует худшую известную долю потерь на канале. Для входящего RTP это потери, делённые на сумму полученных и потерянных пакетов. Для исходящего RTP это потери по отчёту удалённой стороны, делённые на число отправленных пакетов. Расчёт требует минимум 20 пакетов в одном измеренном направлении и хотя бы одного замера времени — джиттера или RTT.

Оценка канала равна 100, умноженным на коэффициенты доступных показателей и округлённым до целого. Между указанными границами коэффициент уменьшается линейно.

| Метрика | Коэффициент 1 | Коэффициент 0 |
| --- | --- | --- |
| Потери RTP | До 0,1% | От 10% |
| Локальный джиттер при приёме в АТС | До 20 мс | От 100 мс |
| RTT по RTCP | До 150 мс | От 800 мс |

[`callQuality()`](../calllive/assets/js/calllive.js#L256) выбирает минимальный балл из каналов, по которым удалось получить оценку. Неполный набор каналов или замеров даёт пометку **частично**. Прочерк означает отсутствие пригодной оценки. Пороговые значения задают шкалу модуля.

[`renderCallDetail()`](../calllive/assets/js/calllive.js#L333) обновляет карточку, пока группа каналов активна. При завершении вызова карточка сохраняет последний состав, замеры, время снимка и балл. После закрытия карточки сохранённое представление удаляется. При истечении сеанса данные в открытой карточке очищаются.

## Файлы версии и подпись

Дерево `calllive/` совпадает с содержимым архива 15.0.6. Комментарии к исходникам и эксплуатационные инструкции в `docs/` лежат рядом с ним. Это позволяет сопоставить файлы на АТС с эталонными SHA-256 из скрипта подписи.

[Скрипт подписи](../dist/15.0.6/calllive-15.0.6-sign-local.php) проверяет установленные файлы, создаёт подписанный список их хешей и помещает его в защищённый каталог FreePBX. В `module.sig` записывается подписанный хеш этого списка. FreePBX проверяет оба уровня. Если FreePBX отклоняет результат, скрипт восстанавливает прежние файлы подписи. Вариант для root-консоли содержит тот же PHP-код и передаёт его в PHP CLI через `/dev/stdin`.
