# Эксплуатация CallLive 15.0.9

[Полное руководство](../calllive/README_RU.md) входит в архив. В нём описаны требования к АТС, AMI, права, хранение и локальная подпись.

## Обновление рабочего модуля

1. В **Отчёты → Монитор телефонии → Диагностика** запишите текущие версии. Если в вашей версии ещё нет этой вкладки, выполните `python3 /opt/freepbx-calllive/collector.py --version` с интерпретатором службы.
2. Сохраните резервную копию АТС и комплект текущей версии. Для CallLive учитывайте каталог истории `/var/lib/freepbx-calllive` и локальные ключи в `/etc/freepbx.secure`. Выберите время с низкой нагрузкой для **Apply Config**.
3. Скачайте [архив 15.0.9](../dist/15.0.9/freepbx15-calllive-15.0.9.tar.gz) и [команду подписи](../dist/15.0.9/calllive-15.0.9-sign-root-command.txt). Загрузите архив через **Module Admin → Upload Module → Монитор телефонии → Upgrade → Process → Confirm**.
4. Вставьте полный текст команды подписи в root-консоль АТС. После сообщения «Локальная подпись CallLive действительна» нажмите **Apply Config**.
5. Откройте **Диагностику**. Если сборщик **15.0.8** работал до обновления, переходите к проверке вызова. При более ранней версии или первом запуске выполните от root команду ниже.

   ```bash
   bash /var/www/html/admin/modules/calllive/deploy/update-root.sh
   ```

   Для нестандартного `AMPWEBROOT` используйте команду из вкладки или [готовую команду](../dist/15.0.9/calllive-15.0.9-update-root-command.txt). Параметр `--check-only` проверяет файлы и AMI перед установкой. Python по пути `/usr/bin/python3.6` поддерживается.

6. Проверьте модуль **15.0.9**, сборщик **15.0.8**, состояние **Сборщик совместим** и доступность истории. Выполните тестовый звонок и откройте завершённый вызов в истории.

## Резервная копия и откат

Копия создаётся в `/var/backups/freepbx-calllive/15.0.9-ДАТА.…`, только для root. Внутри могут быть реквизиты AMI — не публикуйте этот каталог.

Готовая команда отката печатается установщиком. Она выглядит так:

```bash
bash /var/www/html/admin/modules/calllive/deploy/update-root.sh --rollback /var/backups/freepbx-calllive/ТОЧНЫЙ_КАТАЛОГ
```

При неуспешном перезапуске или отсутствии свежего готового снимка вызывается автоматический откат файлов сборщика и AMI-конфигурации. Проверяйте фактический результат в выводе. Если сам откат не удался из-за диска/прав/systemd, вывод содержит путь копии для ручного восстановления.

История не удаляется откатом. Для возврата веб-модуля используйте резервную копию АТС и подпись восстановленной версии.

## Доступ пользователя

В **User Management → Users → Administration GUI** разрешите административный вход, отключите полные права и выберите **Монитор телефонии** в доступных разделах. Вариант **Administrators** также поддерживает выбор отдельного раздела. После изменения прав пользователь должен перелогиниться.

Разрешение даёт чтение всей АТС, включая историю. Настройка порогов — только у полного администратора, запрос защищён CSRF. Веб-интерфейс показывает команду обновления; выполнить её может root в консоли АТС.

## Контроль службы

```bash
systemctl status freepbx-calllive.service --no-pager -l
journalctl -u freepbx-calllive.service -n 50 --no-pager
systemctl cat freepbx-calllive.service
```

При недоступной истории проверьте `/var/lib/freepbx-calllive`, доступ группе веб-процесса и свободное место. Запись `journal.storage_error` в диагностике показывает ошибку сохранения; лимит архива и число пропущенных записей показываются отдельно. Новые функции начинают накапливать данные с запуска 15.0.8.

## Подпись

[PHP CLI-скрипт](../dist/15.0.9/calllive-15.0.9-sign-local.php) и [root-команда](../dist/15.0.9/calllive-15.0.9-sign-root-command.txt) содержат один и тот же код. Он проверяет точный набор файлов релиза и их SHA-256, использует локальный ключ, создаёт подпись в формате FreePBX и проверяет её штатным API. Старый ключ используется повторно; закрытый ключ не покидает сервер. Это локальная подпись конкретной АТС.

Не добавляйте резервные `.bak`, журналы или `__pycache__` в каталог модуля: проверка подписи считает их дополнительными файлами. Установщик и unit включают `PYTHONDONTWRITEBYTECODE=1`; рабочие файлы сборщика лежат отдельно в `/opt` и `/var/lib`.
