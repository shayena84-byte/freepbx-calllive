# Эксплуатация CallLive 15.0.8

[Полное руководство](../calllive/README_RU.md) входит в установочный архив и описывает требования, первое развёртывание, запуск, обновление сборщика, AMI, права, хранение, качество и локальную подпись.

## Порядок обновления с 15.0.4–15.0.7

1. Скачайте [архив 15.0.8](../dist/15.0.8/freepbx15-calllive-15.0.8.tar.gz).
2. Выполните **Module Admin → Upload Module → Монитор телефонии → Upgrade → Process → Confirm → Apply Config**.
3. Выполните от root команду из **Диагностика и обновление**. При стандартной установке:

   ```bash
   bash /var/www/html/admin/modules/calllive/deploy/update-root.sh
   ```

   При другом AMPWEBROOT используйте [готовую команду](../dist/15.0.8/calllive-15.0.8-update-root-command.txt), которая определяет каталог из FreePBX. Сначала можно добавить `--check-only` к вызову `bash …/update-root.sh` для проверки без изменения файлов.
4. Убедитесь, что команда сообщила о работающем сборщике **15.0.8**, AMI и записи истории. Сохраните напечатанный путь резервной копии.
5. Откройте [команду подписи](../dist/15.0.8/calllive-15.0.8-sign-root-command.txt), скопируйте весь текст в root-консоль и дождитесь сообщения об успешной проверке. Подписывается установленная версия 15.0.8 после обновления файлов.
6. Обновите страницу. В диагностике должны совпасть версии модуля и сборщика. Сделайте вызов, дождитесь RTP/RTCP, завершите его и повторно откройте из истории.

Сборщик в 15.0.8 изменился: перенести только веб-модуль недостаточно. Python по пути `/usr/bin/python3.6` поддерживается. Команда находит действующий интерпретатор и сохраняет systemd drop-ins; зависимости ОС не переустанавливаются.

## Резервная копия и откат

Копия создаётся в `/var/backups/freepbx-calllive/15.0.8-ДАТА.…`, только для root. Внутри могут быть реквизиты AMI — не публикуйте этот каталог.

Готовая команда отката печатается установщиком. Она выглядит так:

```bash
bash /var/www/html/admin/modules/calllive/deploy/update-root.sh --rollback /var/backups/freepbx-calllive/ТОЧНЫЙ_КАТАЛОГ
```

При неуспешном перезапуске или отсутствии свежего готового снимка вызывается автоматический откат файлов сборщика и AMI-конфигурации. Проверяйте фактический результат в выводе. Если сам откат не удался из-за диска/прав/systemd, вывод содержит путь копии для ручного восстановления.

История не удаляется откатом. Архив веб-модуля возвращается отдельно в Module Admin, затем нужна подпись соответствующей версии.

## Доступ пользователя

В **User Management → Users → Administration GUI** разрешите административный вход, отключите полные права и выберите **Монитор телефонии** в доступных разделах. Вариант **Administrators** также поддерживает выбор отдельного раздела. После изменения прав пользователь должен перелогиниться.

Разрешение даёт чтение всей АТС, включая историю. Настройка порогов — только у полного администратора, запрос защищён CSRF. Веб-интерфейс показывает команду обновления; выполнить её может root в консоли АТС.

## Контроль службы

```bash
systemctl status freepbx-calllive.service --no-pager -l
journalctl -u freepbx-calllive.service -n 50 --no-pager
systemctl cat freepbx-calllive.service
```

При недоступной истории проверьте `/var/lib/freepbx-calllive`, доступ группе веб-процесса и свободное место. Запись `journal.storage_error` в диагностике показывает ошибку сохранения; лимит архива и число пропущенных записей показываются отдельно. Новые функции начинают накапливать данные с запуска 15.0.8.

## Подпись

[PHP CLI-скрипт](../dist/15.0.8/calllive-15.0.8-sign-local.php) и [root-команда](../dist/15.0.8/calllive-15.0.8-sign-root-command.txt) содержат один и тот же код. Он проверяет точный набор файлов релиза и их SHA-256, использует локальный ключ, создаёт подпись в формате FreePBX и проверяет её штатным API. Старый ключ используется повторно; закрытый ключ не покидает сервер. Это локальная подпись конкретной АТС, не подпись Sangoma.

Не добавляйте резервные `.bak`, журналы или `__pycache__` в каталог модуля: проверка подписи считает их дополнительными файлами. Установщик и unit включают `PYTHONDONTWRITEBYTECODE=1`; рабочие файлы сборщика лежат отдельно в `/opt` и `/var/lib`.
